# 벤치마크: Mutex vs RwLock

프레임워크의 Service Registry는 여러 스레드가 동시에 접근한다. 접근 패턴은
**읽기(이벤트 발행 시 구독자 조회)가 잦고 쓰기(등록/heartbeat)는 드문** read-heavy 성격이다.
이 문서는 레지스트리를 감싸는 락을 `Mutex` vs `RwLock` 으로 바꿨을 때의 성능 차이를
측정하고, "왜 RwLock을 채택했는지"를 수치로 뒷받침한다.

## 측정 도구

[criterion](https://crates.io/crates/criterion) 사용. 한 번 측정이 아니라 워밍업 후
수백~수천 회 반복해 평균과 신뢰구간을 산출하므로, CPU 주파수 변동·OS 스케줄링·캐시
상태 등의 노이즈에 흔들리지 않는 값을 얻는다.

- 벤치 코드: [`framework/benches/lock_bench.rs`](../framework/benches/lock_bench.rs)
- 실행: `cargo bench -p framework`

## 방법론

| 항목 | 값 |
|------|-----|
| 동시 스레드 수 | 8 |
| 스레드당 연산 수 | 2,000 |
| 레지스트리 크기 | 서비스 10개 등록 |
| 읽기 연산 | `subscribers_for(&Event::DoorOpened)` |
| 쓰기 연산 | `mark_heartbeat(name)` |
| 최적화 방지 | 연산 결과를 `std::hint::black_box`로 감쌈 |

- **공정성**: Mutex/RwLock 두 경우 모두 스레드 생성·join 비용이 동일하게 들어가므로,
  두 값의 **차이(delta)는 순수하게 락 동작에서 비롯**된다.
- 워크로드는 두 극단으로 나눠 측정한다:
  - **read-heavy**: 8스레드가 동시에 읽기만
  - **write-heavy**: 8스레드가 동시에 쓰기만

## 결과

측정 환경: 로컬 개발 머신(macOS). 절대값은 하드웨어(코어 수 등)에 따라 달라지며,
아래 각 값은 criterion의 `[하한, 중앙값, 상한]` 신뢰구간이다.

### read-heavy (동시 읽기)

| 락 | 시간 (중앙값) | 신뢰구간 |
|----|--------------|----------|
| Mutex | 59.9 ms | [59.42, 59.86, 60.39] ms |
| **RwLock** | **10.1 ms** | [9.88, 10.05, 10.23] ms |

→ **RwLock이 약 6배 빠름.** 읽기 락은 여러 스레드가 동시에 통과하므로, 코어가 충분하면
스레드 수에 비례해 빨라진다. Mutex는 읽기조차 한 번에 하나씩 직렬화한다.

### write-heavy (동시 쓰기)

| 락 | 시간 (중앙값) | 신뢰구간 |
|----|--------------|----------|
| **Mutex** | **1.31 ms** | [1.306, 1.311, 1.315] ms |
| RwLock | 1.75 ms | [1.750, 1.753, 1.756] ms |

→ **Mutex가 약 30% 빠름.** 쓰기는 RwLock에서도 독점(`write` 락)이라 병렬 이득이 없고,
"현재 독자 수" 등을 추적하는 RwLock의 관리 오버헤드만 남는다. 그래서 단순·가벼운
Mutex가 유리하다.

## 해석

- RwLock은 **만능이 아니다.** read-heavy에선 크게 이기고, write-heavy에선 진다.
  → 락 선택은 **워크로드에 따라** 판단해야 한다.
- 이 프레임워크의 이벤트 라우팅은 읽기(구독자 조회)가 지배적인 **read-heavy**이므로,
  Registry에 **RwLock**을 채택했다.

## 주의 (정직한 전제)

- **read-heavy와 write-heavy의 절대 시간을 서로 비교하면 안 된다** (60ms vs 1.3ms).
  읽기 연산(`subscribers_for`)은 매칭 결과를 `Vec`으로 복사(할당)하므로 무겁고,
  쓰기 연산(`mark_heartbeat`)은 값만 갱신해 가볍다. **비교는 같은 워크로드 안에서만** 유효하다.
- 절대 배수는 하드웨어 코어 수·부하에 따라 달라진다. 결론(방향)은 유지되지만 수치는 환경 의존적이다.
